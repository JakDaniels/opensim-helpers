# osctl – session handoff

Read [PLAN.md](PLAN.md) first: it is the design and holds every decision made so far.

## What this is
osctl ("MIOS 2.0") manages several OpenSimulator instances on one Ubuntu machine: named OpenSim builds from git,
instances and regions, layered ini configuration, systemd units with a tmux console per instance, MariaDB/SQLite,
backups and scheduled restarts; later Robust and a stats web page. C# on .NET 10. It replaces MIOS (PHP), whose
source is at `../MIOS` in the SpatialAudioServer reference tree (ideas only).

  Also `osctl region get`. Next is phase 6 (Robust and local grids).
- Phase 4 (packaging) done: `packaging/linux/` (nfpm.yaml, install scripts, tmpfiles, polkit rule),
  `scripts/build-packages.sh` (needs nfpm), `scripts/test-packages.sh` (CI containers only: no Docker here),
  workflows `ci.yml`, `packages.yml`, `drafts.yml`, `release.yml`, `pages.yml`. The repository is
  `JakDaniels/opensimtools`; v0.1.0 released 2026-11-23; signed apt repository at
  https://jakdaniels.github.io/opensimtools/ (key `packaging/signing-key.asc`, private key only in the secret
  OPENSIMTOOLS_SIGNING_KEY). Not yet tried by hand: the packaged system unit as opensim, the polkit rule, console
  sharing between group members, `sudo osctl db init`.
- Phase 3 (running) done: `src/Osctl/Running/` (InstanceRunner = `osctl run`, InstanceStopper, Supervisor:
  systemd / systemd-user / direct, Tmux, ConsoleCommand, RemoteAdmin), `Cli/RunCommands.cs`. Tried for real with
  OpenSim in direct mode and under systemd user units (then removed). Tests: `Osctl.Tests/Running/` with real tmux
  and a fake OpenSim shell script (skipped without tmux; CI installs it). Next is phase 4 (packaging).
- Phase 2 (instances, regions, config generation, databases) done: `src/Osctl/{ConfigSets,Instances,Databases}`,
  PLAN.md "Configuration generation", "Config sets and grids", "Databases". Tried by hand: a SQLite standalone
  generated by osctl started unattended with OpenSim (tmux, `-inimaster=none`), both regions ready, clean shutdown,
  nothing written into the release bin/. Not yet tried against the real MariaDB (needs `sudo osctl db init`).
  Instance tests: `Osctl.Tests/Instances/InstanceFixture.cs` (fake bin/, fake ports, downloads and database).
  Next is phase 3 (running: systemd + tmux).
- Phase 1 (builds) done: `osctl build …` (`src/Osctl/Builds/`, PLAN.md "Builds"); tried for real with OpenSim
  master + os-webrtc-sas and its core patch. Next is phase 2 (instances, regions, config generation).
  Build tests use real git on local repositories with a fake compile script (`Osctl.Tests/Builds/BuildFixture.cs`).
- Phase 0 (skeleton) done, apart from CI's first run. Solution `src/Osctl.slnx` (`src/Osctl`, assembly `osctl`; `src/Osctl.Tests`, xUnit).
  `dotnet test src` runs the tests; `dotnet run --project src/Osctl -- doctor` checks the machine.
- `Osctl.Ini`: parser and writer that follow Nini's rules (PLAN.md "The ini dialect"), and `IniLoader`, which
  follows OpenSim's `Include-*` handling. Tests read the real files in an OpenSim `bin/`: `../opensim/bin` next to
  this repository, or `OSCTL_TEST_OPENSIM_BIN`; skipped when there is none (as in CI).
- `Osctl.Settings`: paths (`--root`/`OSCTL_ROOT`, default `/`) and `/etc/osctl/osctl.ini` + `secrets.ini`.
- All external programs run through `IProcessRunner` (fake in tests); calls that change the system pass
  `ProcessRunOptions.Change` (or `ChangesSystem: true`) so `--dry-run` prints them instead.
- `osctl init` writes the default files from `src/Osctl/Defaults/` (embedded resources). For a development root:
  `dotnet run --project src/Osctl -- init --root /some/dir`, then `OSCTL_ROOT=/some/dir`.
- Expected errors: throw `OsctlException` (or the ini/settings exceptions); `CliApp.SetAction` turns them into
  one line on stderr and exit code 2.
- A development root with a real OpenSim (build sas-dev, instance Test1, SQLite, direct mode, ports 9002/9003)
  lives in the session scratchpad (`…/scratchpad/devroot`, `OSCTL_ROOT=` it); it may be gone after a reboot.
